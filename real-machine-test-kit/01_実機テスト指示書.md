# 01 実機テスト指示書 — Surfer GRD Converter v0.1.0

目的: Linux側で headless 検証済みの v0.1.0 が、Windows実機の QGIS GUI
でも (a) ZIPから導入でき、(b) Processingツールボックスに現れ、
(c) 4アルゴリズムがGUI操作で期待どおり動く、ことを確認する。

実施環境の記録 (報告書の冒頭に必ず記入):
- QGISのバージョン (ヘルプ > QGISについて の全文、最低でも版数)
- Windowsのバージョン、実施日時、実施者 (Claude / Codex の別)
- できれば QGIS 3.44 LTR で実施。それ以外の版でも可だが版数を明記する。

事前照合:
- キット内 surfer_grd_converter-0.1.0.zip の SHA-256 が次と一致すること
  b7c62c937a207f75f9398fce727dae6d39f0f4c8c5a32d1c02c24dd6085553db
  不一致なら中止して報告する。

作業フォルダ: キット内に out/ を作り、生成物はすべてそこへ出す。

---

## W01 ZIPからインストール

手順: QGIS起動 → プラグイン > プラグインの管理とインストール >
「ZIPからインストール」→ キットのZIPを選択 → インストール。
その後「インストール済み」に Surfer GRD Converter 0.1.0 が現れ、
有効化できること。
期待値: エラーなく導入・有効化できる。プラグイン管理画面の
スクリーンショットを report/shots/W01.png に保存。
注: 過去の実機確認で、プラグイン管理画面が公式リポジトリ取得中に
応答停止した例がある。その場合は無理に待ち続けず、ZIPを展開して
QGISプロファイルの python/plugins フォルダへ
surfer_grd_converter フォルダを配置する代替手順で進め、
その旨を報告書に明記する (合否は代替でも可、経緯は必ず記録)。

## W02 Processingツールボックス表示

手順: プロセッシング > ツールボックス を開き、「Surfer GRD」グループ
(プロバイダ名 Surfer GRD Converter) を確認する。
期待値: 次の4つが表示されること (表示名どおり)。
- GRD to GeoTIFF
- GRD to XYZ (CSV)
- Raster to Surfer GRD
- GRD batch to GeoTIFF
スクリーンショットを report/shots/W02.png に保存。

## W03 GRD to GeoTIFF (基本、GSBG入力)

手順: 「GRD to GeoTIFF」を開き、次を指定して実行。
- Input GRD file: samples/dummy_gsbg.grd
- Output CRS: EPSG:6677
- NoData handling: Surfer blank value as NoData (既定)
- GeoTIFF compression: LZW (既定)
- Output GeoTIFF: out/w03.tif (実行後にレイヤとして読み込む)
期待値:
- 正常終了し、レイヤが表示される
- レイヤのサイズ 5x5、CRS が EPSG:6677
- 値の最小 0 / 最大 24、NoData が 1セルだけ (中央付近)
- レイヤプロパティ (情報タブ) のスクリーンショット W03.png

## W04 GRD to GeoTIFF (NoData変換)

手順: W03と同じ入力で、NoData handling を
「Remap blank cells to a NoData value」にし、NoData value = -9999、
compression = DEFLATE、出力 out/w04.tif。
期待値: 正常終了。統計で最小 0 / 最大 24 のまま、ブランクセルが
NoData (-9999) として扱われ、元の巨大値 1.70141e38 が残っていない
(最大値が巨大値にならないことで確認する)。

## W05 GRD to GeoTIFF (値をそのまま保持)

手順: NoData handling を「Keep values as-is」にし、出力 out/w05.tif。
期待値: 正常終了し、最大値が約 1.70141e38 (ブランク値そのまま) に
なること。これは仕様どおりの「保持」の確認であり、不具合ではない。

## W06 GRD to XYZ (CSV)

手順: 「GRD to XYZ (CSV)」を開き、次を指定して実行。
- Input GRD file: samples/dummy_gsag.grd
- Exclude Surfer blank values: ON (既定)
- Output CSV: out/w06.csv
期待値:
- ログに「Wrote 24 grid points」と出る (25セル − ブランク1)
- CSVはヘッダ x,y,z ＋ 24行
- 先頭データ行が 105,145,0、最終データ行が 145,105,24 であること
  (セル中心座標。GSAGファイル内は下段から格納されるが、GDAL経由の
  出力は北側の行から並ぶため、この順序が正しい。検証済み)
続けて OFF でもう一度実行し (out/w06_all.csv)、25行になり、
z が約 1.70141e38 の行が1行含まれることを確認する。

## W07 Raster to Surfer GRD

手順: まず samples/dummy.tif をレイヤとして読み込む。次に
「Raster to Surfer GRD」を開き、次を指定して実行。
- Input raster: dummy.tif のレイヤ
- Surfer GRD format: GSBG (Surfer 6 binary) (既定)
- Output GRD: out/w07_gsbg.grd
期待値: 正常終了。出力ファイルの先頭4バイトが「DSBB」であること
(メモ帳等で判別できなければ、サイズと生成時刻の記録で代用可)。
続けて format = GSAG でも実行し (out/w07_gsag.grd)、先頭が
「DSAA」で始まるテキストであることを確認する。
注: 選択肢に GS7BG が**無い**ことが v0.1 の仕様 (書き出し不安定のため
除外)。無いことを報告書に明記する。

## W08 GRD batch to GeoTIFF

手順: samples フォルダをコピーして out/batch_in/ を作る
(.grd 2ファイルが入った状態)。「GRD batch to GeoTIFF」を開き、
- Input folder: out/batch_in/
- Output CRS: EPSG:6677
- Output folder: out/batch_out/
期待値: dummy_gsag.tif と dummy_gsbg.tif の2ファイルが生成され、
ログに各ファイルの成功が表示される。

## W09 範囲の記録 (合否判定しない観察項目)

W03の出力レイヤについて、レイヤプロパティに表示される範囲 (Extent)
の X/Y 最小・最大を報告書にそのまま転記する。
理由: Surfer GRDはノード (点) データ、GDAL/QGISのラスタはセル扱いの
ため、範囲が半セルずれる可能性が未確認事項として残っている。
ここでは**記録のみ**とし、合否は判定しない。実物のユーザーGRDでの
確認は別件 (残作業2) で扱う。
