## ねらい

Muse (ハブ側) や和田さんが「実機タスク」をフォルダに放り込むだけで、
PC側が順番に受け付け、空き時間に1件ずつ処理し、報告を戻す。
和田さんが PC の前に座って起動の一言を入れる手間をなくす。

## 仕組み (最小構成)

置き場所: Drive同期フォルダ配下に専用キューを作る (例: PC実機キュー/)。
同期により、投げ込みと報告回収は Drive 経由で完結する。

- inbox/    投げ込まれたタスク (1タスク = 1フォルダ、中に指示書と素材)
- running/  処理中 (PC側ワーカーが inbox から先着順に1件だけ移す)
- done/     完了 (報告書と生成物を添付)
- failed/   失敗 (エラー記録つき、自動リトライはしない)

PC側ワーカー: 常駐はさせず、Windows タスクスケジューラで
15〜30分おきに起動する短い PowerShell スクリプトにする。
処理は次のとおり。

1. running/ が空でなければ何もしない (同時実行は1件だけ)
2. inbox/ の最古のタスクを running/ へ移す (受付印として時刻を記録)
3. タスク種別が許可リスト (下記) にあれば、Claude Code / Codex を
   ヘッドレスで起動し、指示書のパスだけを渡して実施させる
4. 終了したらフォルダを done/ (または failed/) へ移し、報告を置く
5. ログは PC側ローカルにも残す (共有に出さない情報はそちらへ)

## 安全の線引き (重要)

- 自動実行してよいのは許可リストのタスクだけにする。初期は
  「QGISプラグインの実機テスト (本キット形式)」のみ。
- 削除、送信、公開、購入など不可逆な操作を含むタスクは自動実行せず、
  受付だけして和田さんの確認待ちに止める (running に入れない)。
- キューに入った指示書は「外部から来た文書」として扱い、指示書に
  書かれていない操作へは広げない。クレジット上限 (1タスクあたりの
  回数・時間) をワーカー側で打ち切る。
- 秘密情報 (トークン、client_secret 等) をキューに入れない。

## クレジット設計

- 1回の起動で1タスクだけ処理し、長大な対話セッションを維持しない。
- スクリプトで済む前処理 (ハッシュ照合、フォルダ準備、機械的な検証)
  は AI を介さずワーカーの PowerShell で行い、AI の仕事を
  「GUI確認と判定」だけに絞る (04_クレジット節約策.md と共通)。
- 失敗タスクを自動で再投げしない。原因を見てから人が再投入する。

## 設置手順 (承認後に実施)

1. PC側でキューフォルダとワーカー用スクリプトを配置 (実行キット化)
2. タスクスケジューラ登録 (間隔と同時実行1件を明記)
3. ダミータスクで受付→実行→報告→done移動を通し確認
4. ハブ側 (Muse) が Drive の done/ を巡回で拾い、結果を報告する
