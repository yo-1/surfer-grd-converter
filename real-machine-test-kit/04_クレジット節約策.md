# 04 クレジット節約策 — PC側AI (Claude / Codex) が守るルール

背景: 実機テストを対話セッションでだらだら進めるとクレジット消費が
激しい。下のルールは、このキットの実施と、今後の実機タスク共通の
節約策として実施者AIが守ること。

## ルール

1. **1タスク1セッション、一括実施。** 項目ごとに報告・確認を挟まず、
   指示書の全項目を通しで実施し、報告は最後に1回だけ書く。
2. **二重実施しない。** Claude と Codex の両方に同じテストをさせない。
   担当は1者。もう一方は報告のレビューだけなら安い。
3. **リトライは1回まで。** 同じ失敗を繰り返さない。2回目も失敗したら
   エラー全文と画面状態を報告に残して次へ進む。原因不明の試行錯誤で
   セッションを伸ばさない。
4. **機械で済むことは機械で。** ハッシュ照合、ファイル数・サイズ確認、
   CSV行数カウント、出力ファイルのヘッダ確認などは、画面操作や
   対話でなく PowerShell / Python の一発実行で済ませる。
   QGISのPythonコンソールや qgis_process で確認できる項目は
   GUIのクリック反復で確認しない。
5. **スクリーンショットは指定分だけ。** 本キットでは W01/W02/W03 の
   3点＋失敗時の画面のみ。探索的に撮り増やさない。
6. **長いログを会話に貼らない。** ログはファイルに保存し、報告には
   要点とファイル名だけを書く (入力トークンの節約)。
7. **打ち切り条件。** 1タスクで想定時間 (目安60分) を超えたら、
   途中経過を報告ファイルに書いて終了し、人の判断を待つ。
8. **モデル選択。** 定型の実機テストは、実施側で選べるなら
   最上位モデルでなく実務向けモデルを使い、最上位は設計・判定の
   局面 (ハブ側) に温存する。

## ハブ側 (Muse) の節約策

- 指示書に期待値を数値で書き切り、実施側が探索・推測する余地を減らす
  (本キット 01 の形式)。
- 報告はチェックリスト形式で受け、追加質問の往復を最小にする。
- 自動受付キュー (03) が実現したら、前処理をワーカーのスクリプトに
  移し、AIの担当を GUI確認と判定だけに狭める。
